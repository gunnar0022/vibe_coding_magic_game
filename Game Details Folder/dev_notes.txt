IMPLEMENTATION GOAL:
---------------
Expand the magic system to support deeper world interactions and introduce a hand-based equipment constraint that affects spellcasting and object manipulation.

====================
STAGE 1: TREE INTERACTION REFINEMENT

Focus exclusively on interactions involving trees.

Trees must have:

A health value

A burning status effect

Clear despawn behavior

Burning behavior:

When a tree is set on fire, it should take continuous damage over time.

Burning damage must persist until explicitly removed or the tree is destroyed.

When tree health reaches zero due to burning, the tree must despawn from the map.

Extinguishing behavior:

Applying any water-based or wet status effect to a burning tree must immediately remove the burning status.

Extinguishing does NOT restore lost health.

After extinguishing, the tree remains damaged and may be re-ignited later.

This stage is complete once:

Fire damages trees over time

Water reliably cancels burning

Tree health persists correctly

Tree despawns at zero health

====================
STAGE 2: HANDS, SUMMONED WEAPONS, AND SLASHING INTERACTIONS

Introduce a hand-occupancy system.

Player hand rules:

The player has two hands.

Casting spells requires at least one free hand.

Certain summoned weapons occupy one or both hands.

Only one summoned weapon may exist at a time.

Introduce three new base spells:

斧 (Axe)

刀 (Sword)

大 (Great / Size modifier)

These spells may combine with existing ones to create weapon variants.

Weapon definitions (use English internally for clarity):

Sword:

One-handed

Fastest swing speed

Lowest slashing power

Axe:

One-handed

Faster swing than large weapons

Lower slashing power than large variants

Big Sword:

Two-handed

Slow swing speed

High slashing power

Big Axe:

Two-handed

Slowest swing speed

Highest slashing power

Each weapon must define:

Hand requirement (1 or 2)

Cooldown / swing speed

Damage type (slashing)

Slashing power (numeric or tiered threshold)

WEAPON USAGE

Left mouse click performs a weapon attack if a summoned weapon is currently held.

The attack should be a horizontal swing centered on the player.

The swing must respect the weapon’s cooldown and cannot be spammed.

The swing should apply slashing damage to all valid targets intersecting its hit area.

Directional aiming is not required for this sprint; the swing may be symmetric or player-facing.

Tree slashing rules:

Trees must define a slashing damage threshold required to be cut down.

Only slashing-type attacks meeting or exceeding this threshold may damage trees.

Attacks of the wrong damage type or insufficient power must have no effect.

Tree destruction outcome:

If a tree is destroyed via slashing damage, it must be replaced with a log object.

The log exists as a physical world object.

Log interaction rules:

At base player strength, logs cannot be picked up.

Logs should respond to force spells exactly as rocks currently do.

In future systems, logs may be carried using both hands, but this is NOT required for this sprint.

Weapon summoning and dismissal:

Summoning a weapon costs magic and occupies hands immediately.

Dispelling a weapon:

Bound to key 'R'

Is instant

Costs no magic

Casting restrictions:

While holding a two-handed weapon, the player cannot open the spellcasting menu.

One-handed weapons still allow spellcasting if one hand is free.

This stage is complete once:

Weapons can be summoned and dismissed correctly

Left click triggers weapon swings with cooldowns

Hand occupancy restricts spellcasting as defined

Trees respond correctly to slashing thresholds

Logs spawn and behave as expected

CONTROLS:
---------
- WASD / Arrows: Move
- SPACE (hold): Open magic menu
- Left-click: Attack with weapon / Select in menu
- Right-click: Cancel spell selection
- E: Interact with NPCs/objects
- R: Dismiss summoned weapon
- I: Introspect (reflect on last spell)
- J: Open spell journal
- H: Show help
- TAB: Open/close game menu (game continues running)
- ESC: Context-sensitive back/pause:
  * If paused -> Unpause
  * If magic menu open -> Cancel spell
  * If dialogue open -> Advance/close
  * If journal open -> Close journal
  * If game menu open -> Close menu
  * If spell editor open -> Return to game menu
  * If nothing open -> Pause game

MENU SYSTEM:
------------
- Game menu (TAB): World keeps running while open
- Journal (J): Can be open simultaneously with game menu (side by side)
- TAB while journal open: Opens menu alongside journal
- Spell customization: Auto-saves all changes, ESC returns to game menu
- "Resume" button: Clean slate - closes ALL open UI (menu + journal)
- Pause (ESC when nothing open): Freezes everything
