PART 1: ELEMENTS VS ATTRIBUTES
================================================================================

First, let's distinguish between ELEMENTS (active forces) and ATTRIBUTES (inherent properties).

ELEMENTS (can be applied via magic or environment):
- Fire
- Water
- Ice
- Electric
- Wind
- Earth
- Light
- Dark
- Spirit

ATTRIBUTES (inherent to objects, not applied):
- Organic (trees, plants, creatures, player)
- Metal (weapons, armor, ore)
- Plant (subset of organic - trees, grass, flowers)
- Liquid (water bodies, potions)
- Stone (rocks, boulders, walls)


- Plant = can grow, photosynthesis, rooted
- Organic = living tissue, can burn, can heal

## ANSWER: Yes, they should be different. This will allow us to distinguish between plants and living things. Plants can be flammable, but the player wouldn't be in the same way. This way we can also put fabric clothes in the organic category, making them burnable. Plant attribute things would have to react a bit differently to organic, maybe if set on fire, they'll burn until destroyed, but organic things don't necessarily do that.

PART 5: CHAIN REACTION RULES
================================================================================

The core idea: reactions should CASCADE through connected objects.

Example chain:
1. Player casts Fire on Tree A
2. Tree A gains Burning status
3. Tree A is adjacent to Tree B (both have Plant attribute)
4. After X seconds, fire spreads to Tree B
5. Tree B was Wet, so fire is extinguished immediately
6. Tree B loses Wet status

Example chain with electric:
1. Player casts Electric on Water puddle
2. Water has Liquid attribute, Electric + Liquid = Conductivity
3. All entities standing in connected water take shock damage
4. Enemy in water has Metal armor, takes bonus damage

PART 6: IMPLEMENTATION QUESTIONS
================================================================================

Q1: How do we represent attributes on objects?
  I think the tag system is best, and maybe include Boolean flags attached to the object. Use tags for what the object is, and Booleans to flip yes or no depending on surrounding interactions. 

Q2: How do we handle reaction priority?
    better just use a que system. If they seem to happen at the exact same time, make a set priority based on how much that element is likely to be able to overwrite other statuses. 

Q3: How do reactions spread spatially?

	depends on the reaction. be able to handle all 3. 

    - Adjacent tiles only?
    - Radius-based?
    - Material-connection based (all connected water)?

Q4: How long do status effects persist?

	again, each of these can be possible. I think they should all have a default timer, but can be overwritten by blending. 
    - Timed duration?
    - Until countered?
    - Based on intensity/source power?

Q5: Can the player have attributes?

Most of the above, organic by default, wearing or holding metal will add temporary tags of sorts. standing in water should apply wet, not liquid. 

    - Player is Organic by default
    - Wearing metal armor adds Metal attribute?
    - Standing in water adds temporary Liquid-adjacent status?
